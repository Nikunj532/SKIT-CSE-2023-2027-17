# Adhikar Setu — Database Design & Data Architecture

This document specifies the database schemas, MongoDB entities, collection validators, and data retrieval architecture for **Adhikar Setu**.

---

## 1. Scheme Entity

Government welfare schemes are stored and retrieved for discovery, searching, and eligibility matching.

### 1.1 Field Specifications

| Field | Type | Required | Description |
|---|---|---|---|
| `scheme_id` | `string` | Yes | Unique scheme identifier (e.g. `sch_pm_kisan`) |
| `name` | `string` | Yes | Official scheme title |
| `description` | `string` | Yes | Comprehensive scheme summary |
| `ministry` | `string` | No | Nodal ministry or department |
| `state` | `string` | No | Applicable state (e.g. `Rajasthan`) or `Central` / `All` |
| `category` | `string` | Yes | Domain category (e.g. `Agriculture`, `Education`, `Health`, `Housing`) |
| `benefits` | `list[string]` | No | Structured list of direct citizen benefits |
| `eligibility` | `list[string]` | No | Stated criteria for citizen qualification |
| `documents` | `list[string]` | No | Mandatory documentation required to apply |
| `application_process` | `list[string]` | No | Procedural steps to submit an application |
| `official_url` | `string` | No | Direct link to official government portal |

### 1.2 Retrieval & Search Capabilities
Scheme discovery supports:
1. **Keyword Text Search (`q`)**: Case-insensitive multi-term search across scheme `name`, `description`, `ministry`, and `category`.
2. **Category Filtering (`category`)**: Exact or substring category match (e.g. `Agriculture`, `Health`).
3. **Geographic Filtering (`state`)**: Matches state-specific schemes while including nationwide `Central` / `All` schemes.
4. **Pagination**: Controlled via `page` (1-indexed) and `limit` (1 to 100), returning total matches and page counts.

## 2. Citizen Profile MongoDB Entity (`profiles` collection)

The citizen profile entity stores demographic and socio-economic information required to assess eligibility for government schemes.

### 2.1 MongoDB Document Structure

```json
{
  "_id": "ObjectId('670678e5f1a23b4c5d6e7f80')",
  "profile_id": "prof_a1b2c3d4",
  "name": "Nimisha Mangal",
  "age": 21,
  "gender": "Female",
  "state": "Rajasthan",
  "district": "Jaipur",
  "income": 250000.0,
  "occupation": "Student",
  "category": "General",
  "disability_status": "No",
  "qualification": "B.Tech Data Science",
  "created_at": "2026-10-09T18:00:00Z",
  "updated_at": "2026-10-09T18:00:00Z"
}
```

### 2.2 Field Descriptions & Validation Constraints

| Field | BSON / Pydantic Type | Constraints | Description |
|---|---|---|---|
| `_id` | `ObjectId` / `string` | Generated by MongoDB | Internal database document identifier |
| `profile_id` | `string` | Unique, pattern: `prof_<hex>` | Public business identifier for API operations |
| `name` | `string` | Length: 2 to 100 chars | Full name of the citizen |
| `age` | `int` | $0 \le \text{age} \le 120$ | Age in completed years |
| `gender` | `string` | Required | Gender (e.g. `Male`, `Female`, `Transgender`, `Other`) |
| `state` | `string` | Min length: 2 chars | State of residence (used for state scheme matching) |
| `district` | `string` | Min length: 2 chars | District of residence |
| `income` | `double` / `float` | $\text{income} \ge 0$ | Annual household income in INR |
| `occupation` | `string` | Min length: 2 chars | Primary employment or occupation |
| `category` | `string` | Required | Social category (e.g. `General`, `OBC`, `SC`, `ST`, `EWS`) |
| `disability_status` | `string` | Default: `"No"` | Disability indicator (`Yes` / `No`) |
| `qualification` | `string` | Optional | Highest educational qualification |
| `created_at` | `string` (ISO 8601) | Auto-generated UTC | Creation timestamp |
| `updated_at` | `string` (ISO 8601) | Auto-generated UTC | Last update timestamp |

### 2.3 MongoDB Collection Schema Validator (`$jsonSchema`)

```javascript
{
  $jsonSchema: {
    bsonType: "object",
    required: [
      "profile_id", "name", "age", "gender", "state", "district",
      "income", "occupation", "category", "created_at", "updated_at"
    ],
    properties: {
      profile_id: { bsonType: "string", description: "Unique business profile identifier" },
      name: { bsonType: "string", minLength: 2, maxLength: 100 },
      age: { bsonType: "int", minimum: 0, maximum: 120 },
      gender: { bsonType: "string" },
      state: { bsonType: "string", minLength: 2 },
      district: { bsonType: "string", minLength: 2 },
      income: { bsonType: ["double", "int"], minimum: 0 },
      occupation: { bsonType: "string", minLength: 2 },
      category: { bsonType: "string" },
      disability_status: { bsonType: "string" },
      qualification: { bsonType: ["string", "null"] },
      created_at: { bsonType: "string" },
      updated_at: { bsonType: "string" }
    }
  }
}
```

### 2.4 Indexing Specifications

To ensure optimal query performance and business constraint enforcement, the following indexes are defined:

1. **`idx_profile_id_unique`**: `{ profile_id: 1 }` (Unique index) — Enforces unique business identifiers across all citizen profiles.
2. **`idx_profile_state`**: `{ state: 1 }` — Accelerates geographic filtering and regional scheme alignment.
3. **`idx_profile_category`**: `{ category: 1 }` — Optimizes social category and quota matching.
4. **`idx_profile_created_at`**: `{ created_at: -1 }` — Enables efficient chronological sorting.

## 3. Persistence Architecture & Environment Configuration

The backend persistence layer implements a dual-tier strategy:

1. **MongoDB Primary Storage:**
   - Active when MongoDB server is reachable via connection string configured in `MONGODB_URI` (default: `mongodb://localhost:27017`).
   - Database name configured via `MONGODB_DB_NAME` (default: `adhikar_setu`).
   - All connection credentials remain strictly in environment variables (`.env`).
2. **Local Fallback Storage:**
   - When MongoDB is unavailable or during standalone offline testing, `ProfileService` transparently persists to local file storage (`data/profiles.json`).
   - Ensures continuous developer workflow and test suite execution without external service hard-dependencies.

## 4. Integrity and Government Verification Notice

Only verified government-source information is presented to citizens as official scheme information. Official portal links (`official_url`) are maintained for all schemes.
